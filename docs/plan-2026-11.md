# Plan: one program system for the QCrypt, TQC and QIP websites

## Why

The three sites run the same Hugo theme (devfest fork, Hugo 0.140). The schedule and paper machinery is already there. QCrypt 2026 doesn't use it:

- **Hand-written schedule.** `content/2026/schedule/_index.md` is about 1,480 lines of HTML cards, with no `data/schedule-2026.yml`. Talk slots are free text like "#63 Compressed Permutation…". The HTML is also broken: one `<a href=…Bozzio"` is never closed.
- **Papers are not linked to the schedule.** The accepted-papers list doesn't link to the schedule, and the schedule doesn't link back.
- **Presenters are not recorded anywhere** for 2025 or 2026.
- **Videos aren't linked.** They are uploaded (playlist "QCRYPT 2026 - uOttawa" on the QCrypt channel), but nothing points to them. In 2025 the videos were matched to papers by list order (`videoIds:`), which already breaks in `2025/sessions/contributed/4b.md`.
- **Pages copied from 2025 still have leftovers:** `chair: None`, `lecture/Pan`, `presentations.md` still says 2025, and the 2025 schedule page prints a registration table for 2026.

TQC 2026 does this better:

- Session pages list HotCRP paper ids (`papers: [11, 129]`), and `schedule-2026.yml` places those sessions in time slots and rooms, with parallel tracks.
- Presenters are shown in bold. `scripts/mark_presenters.py` derives them from the registration export into `presenters-2026.yml`, and a hand-edited `presenters-overrides-2026.yml` corrects mistakes.
- Proceedings DOIs (`proceedings-2026.yml`) and extended-abstract PDFs are linked by paper id.

TQC has its own gaps: there are no anchors linking schedule and papers in either direction, and no videos for 2026.

Each site has drifted its own copy of the theme. QIP has a talk-type filter and a schedule generator, QCrypt has session chairs and guards against missing papers, and TQC has rooms, parallel tracks and presenters.

**Goal:** one shared, documented pipeline that takes the HotCRP export to a fully linked schedule, used by all three sites, then retrofit QCrypt 2026 with it.

## How the pieces work

### A. Hugo modules

A Hugo module is a git repository whose folders (`layouts/`, `assets/`, `static/`, `data/`, …) Hugo merges into a site at build time, as if they were the site's own files.

1. **Create the shared repo.** For example `github.com/IAQI/conference-program`. It holds only the program machinery:
   - `layouts/partials/paper*.html`, `schedule-session.html`, `location.html`
   - `layouts/schedule/`, `layouts/sessions/`
   - the shortcodes `papers-accepted`, `posters-accepted`, …
   - the Python scripts

   Logos, SCSS and the home page stay in each site's own theme.
2. **Import it in each site.** In `hugo.toml`:
   ```toml
   [module]
     [[module.imports]]
       path = "github.com/IAQI/conference-program"   # shared program templates
     [[module.imports]]
       path = "devfest-theme-hugo"                    # site's own visual theme in themes/
   ```
   Running `hugo mod init github.com/IAQI/qcrypt-website` once creates a `go.mod`. That file pins the exact commit of the shared repo, much like `package-lock.json`.
3. **Overrides.** When the same file exists in several places, Hugo uses the first one in this order: the site's own `layouts/`, then the first import, then the next. So QIP can keep a special version of one file by putting it in its own `layouts/` and still take everything else from the shared repo.
4. **Updating.** Fix a template once in the shared repo, then run `hugo mod get -u` in each site and commit the new `go.mod`/`go.sum`. Each site moves to the new version when it chooses, so nothing breaks unexpectedly.
5. **Build requirement.** Downloading modules needs `go` at build time. Netlify's build image has it. To avoid depending on Go at all (Netlify or Azure), run `hugo mod vendor`: the shared files are copied into `_vendor/` and committed, and Hugo uses them with no download.
6. **Local development.** Set `HUGO_MODULE_REPLACEMENTS="github.com/IAQI/conference-program -> ../../conference-program"` (or a `replace` line in `go.mod`). `hugo server` then uses your local checkout of the shared repo live.

A **git submodule** is the alternative: the same shared repo nested under `themes/`, listed as a second theme. It needs no Go and no `go.mod`, but updates are `git submodule update --remote`, and forgetting `--recursive` on clone gives empty layouts. A Hugo module with vendoring is the cleaner of the two, so this plan uses it.

### B. Presenter highlighting (TQC's `mark_presenters.py`)

1. **Input.** The registration export (`.xlsx` or `.csv`). Each row has *First name*, *Last name*, *Will you be presenting?* (talk / poster / both / no) and *Title of presentation*.
2. **Matching, title first.** For each row that says it presents, the declared title is fuzzy-matched against the titles in `accepted-papers-YYYY.json` (talks) or `posters-YYYY.json` (posters) only.
   - A match needs similarity ≥ 0.85, or a substring match where both strings are at least 20 characters long.
   - The registrant's name is used only afterwards, to pick which author of that paper to mark.
   - Duplicate rows are dropped. For someone who lists several talks, the script works out which one by elimination.
3. **Output.** `data/presenters-YYYY.yml` maps each paper id to its presenters, e.g. `"63": ["Alex Lombardi"]`. `presenters-overrides-YYYY.yml` lets you fix any entry by hand and wins over the computed value. Rows the script can't resolve are printed for a human; it never guesses.
4. **Rendering.** `partials/paper-authors.html` compares each "First Last" against that list. It shows a match in **bold** on paper lists and session pages, and in *italics* on the compact schedule cards.
5. **Prerequisites for QCrypt.**
   - The registration form needs the "presenting? / title" questions. For 2026, check whether the uOttawa registration export has them. `private_data/qcrypt2026-authors.csv` is the HotCRP author list, which has no presenter information.
   - If the export lacks them, fill the overrides file by hand from the PC chair's knowledge or the session chairs' notes.
   - For QIP, the video titles already carry the speaker ("Bruno Cavalar: A Meta-Complexity…"), so the video importer below can also propose presenters.

### C. Video linking (new, replaces `youtube-YYYY.json` and order-based `videoIds`)

- **Fetch.** `fetch_videos.py --year 2026 --playlist URL [--playlist URL …]` runs `yt-dlp --flat-playlist -J`. It accepts several playlists; QIP 2026 has 11, one per track.
- **Match.** Each video title is fuzzy-matched against:
  1. paper titles, giving a paper id;
  2. invited, tutorial and industry session titles, giving a session path such as `invited/Goldin`.

  It strips prefixes like "Invited Talk:" or "Speaker: " and keeps the speaker name as `presenter` when one is present.
- **Output.** `data/videos-YYYY.yml`, plus a hand-edited `videos-overrides-YYYY.yml`; unmatched videos are printed:
  ```yaml
  papers:   { "63": {id: "MHJcaaysIN0", presenter: "…"} }
  sessions: { "invited/Goldin": {id: "dCibf89nwI8"} }
  ```
- **Templates** read this file, falling back to `youtube-2023.json` and to `videoId`/`videoIds` in front matter for old years. Nothing is matched by position any more.
- **Current state.** The QCrypt 2026 playlist currently has 16 videos, with titles only. Re-run the script as more videos are uploaded.

## The streamlined pipeline (documented once, in the shared repo's README)

| Step | When | Command / input | Output |
|---|---|---|---|
| 0 | New year | `create-year.sh YEAR` (from TQC) | content skeleton, empty data files, menu |
| 1 | Acceptance | HotCRP JSON exports (talks, posters; a second HotCRP instance gets `adjust_pids.py --offset 1000`) → `sanitize_hotcrp_json.py` (QIP version, with arXiv lookup). Raw exports go in git-ignored `private_data/`, **never** `data/` | `accepted-papers-Y.json`, `posters-Y.json`, so the accepted lists go live at once |
| 2 | Program fixed | PC chair fills **one** `private_data/program-Y.csv` (or a Google Sheet export) with columns `day, time, end, session_id, session_title, format, room, chair, pids, speaker_key` → `generate_schedule.py` (generalized from QIP's `generate_schedule_2026.py`) | `schedule-Y.yml`, `locations-Y.yml`, `content/Y/sessions/*.md`. Re-runnable: it only rewrites generated front-matter keys and keeps hand-written fields (note, cardOptions, abstract body) |
| 3 | Registration closes | `mark_presenters.py --year Y --registrations …` | `presenters-Y.yml` (+ overrides) |
| 4 | After the conference | `fetch_videos.py`; slide files dropped as `content/Y/sessions/slides/<pid>.pdf`; `proceedings-Y.yml` (DOIs); extended abstracts `<pid>_ext_abst.pdf` | links appear automatically everywhere |

The scripts move into one folder, `scripts/` in the shared repo, with a common `--year`/`--data-dir` interface and one `requirements.txt` (PyYAML, yt-dlp). Today copies are scattered across `qcrypt/static/python-scripts`, `qcrypt/merge_papers.py`, `tqc/scripts` and `qip/scripts`.

## Template features in the shared module (the merged superset)

The starting point is TQC's versions: parallel tracks, rooms, presenters. Added to those:

- **From QCrypt:** the `chair` field and guards against missing papers.
- **From QIP:** the `talk-type` filter and `mergedwith` as a list.
- **New: links between schedule and papers.**
  - `paper.html` gets `id="paper-{pid}"`.
  - Each paper on the accepted lists shows "→ Tue 26 Aug, 10:30, Session *Algorithms*". This comes from a small index partial that scans `site.Pages` for `papers:` front matter.
  - Each paper on a schedule card links to the paper on its session page.
- **New: icons on schedule cards and paper entries** for ▶ video, slides, arXiv, proceedings and extended abstract.
- **Configurable:** the conference name for file prefixes (no more hard-coded `QCrypt%sTalkSlides`/`QCrypt2021Poster`), via `params.programPrefix`.
- **Fixes:** the poster pages that omit `year=` (TQC bug) and the dead poster-PDF branch that reads `decision`.

## Phases

1. **Build the shared module** (`IAQI/conference-program`).
   - Extract the superset templates and scripts and add the new features above.
   - Test it against a copy of QCrypt data from 2023 to 2026.
2. **Retrofit QCrypt 2026** (this repo, branch off `main`).
   - Parse the existing hand-written HTML once into `program-2026.csv` (day, time, session, pid / speaker link), then run `generate_schedule.py`.
   - Keep the URLs `/2026/sessions/contributed/<pid>` stable.
   - Delete the HTML from `schedule/_index.md` and `_index-with-paper-links.md`.
   - Fill in chairs, remove the copied 2025 lecture and dinner pages (after confirming with you), fix `presentations.md`, and import videos and presenters.
3. **Clean up older QCrypt years** (small).
   - 2025: remove the stray registration table from the schedule page, and move videos to `videos-2025.yml`, which fixes the `4b` mismatch.
   - 2023: `videoID` → `videoId` in 7 pages.
   - Move the untracked `data/qcrypt2025-*.json` to `private_data/`, delete `patch.diff`, and add `private_data/` to `.gitignore`.
4. **Move TQC and QIP to the module.**
   - Delete their overlapping theme files and keep any site-specific ones in `layouts/`.
   - Move TQC's untracked raw HotCRP exports out of `data/`. They include rejected papers.
   - Each site gets its own PR.
5. **Docs.**
   - The shared README holds the pipeline table above.
   - Each site's README links to it and keeps only site-specific notes. QIP's README is still marked "TODO".

## Verification

- **Before/after build diff.** Run `hugo --gc --minify` in each site before and after moving to the module, then `diff -r` the `public/` folders for past years. Only intended changes may appear: new anchors, new links, bug fixes.
- **Visual check.** Use `hugo server` with the browser on the QCrypt 2026 schedule, a session page, and the accepted-papers page. Click schedule → paper → video → back.
- **Script dry runs** on the real 2026 data:
  - `fetch_videos.py`: all 16 current videos matched, or listed for review.
  - `generate_schedule.py`: idempotent, so a second run gives no git diff.
  - `mark_presenters.py`: reports unresolved rows.
- **Link check:** `htmltest` or `lychee` on `public/2026/`, so there are no broken internal links or anchors.
- **Netlify deploy preview** for each site's PR.
